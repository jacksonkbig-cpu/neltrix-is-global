# Prisma setup

1. Configure `DATABASE_URL` and `DIRECT_URL` in local environment and hosting secrets.
2. Run `npm install` and `npx prisma generate`.
3. For local development, run `npx prisma migrate dev --name initial_logistics`.
4. Inspect the generated migration SQL before applying it anywhere shared.
5. For staging/production, commit the reviewed `prisma/migrations` directory and run `npx prisma migrate deploy` from a release job.
6. Optional seed: set `SEED_ADMIN_EMAIL` and `SEED_ADMIN_PASSWORD_HASH`, then run `npm run db:seed` only in a non-production database by default.

The seed expects a secure password hash generated by a suitable password-hashing library (Argon2id recommended). It never accepts or stores a plaintext password. The demo shipment is explicitly labelled as demo data.

Do not point `prisma migrate dev` at production. Do not remove existing Supabase tables until staff authentication and quote records have a tested migration plan.
